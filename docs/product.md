> **Канон для:** продуктовых требований (F0–F9), JTBD, ЦА, антискоупа, монетизации, метрик, дорожной карты, рисков.

## 1. Суть продукта

Бот, который автоматически приходит на онлайн-встречи (Zoom, Google Meet, Яндекс Телемост), записывает разговор, создаёт структурированный конспект с задачами и присылает всё в Telegram-бот.

## 2. Job-to-be-done

**Главный джоб:** «Не терять то, что было решено на встрече, и не тратить время на ручную фиксацию».

- **Слой 1 — Экономия времени.** Руководитель не конспектирует сам, не выгружает запись из Zoom, не пересылает вручную. Бот прислал → переслал в чат команды. 30 секунд вместо 15 минут.
- **Слой 2 — Контроль договорённостей.** Конспект с задачами виден всей команде. Нет отмазки «я не слышал». Задачи не теряются.
- **Слой 3 — База знаний (wow-фактор).** Накопленные расшифровки становятся инфраструктурой управления: карты развития сотрудников, портреты должностей, обратная связь о себе как о руководителе.

## 3. Целевая аудитория

### Основной сегмент

| Параметр | Описание |
|---|---|
| Роль | Руководители команд 5–70 человек, предприниматели |
| Созвонов в неделю | 5–20 (планёрки, 1-on-1, стратегические сессии) |
| Платформы встреч | Zoom, Google Meet, Яндекс Телемост |
| Мессенджер | Telegram (основной рабочий канал) |
| Готовность платить | Да — привыкли к SaaS-подпискам |
| Канал привлечения | Личный бренд (совокупно 50K+ подписчиков, рост) |

### Вторичный сегмент (виральный)

Менеджеры, кураторы, продажники — сотрудники предпринимателей из основного сегмента. Владелец покупает для себя, потом разворачивает команде. Один платящий = несколько пользователей.

### Антиперсона — кому НЕ продаём

- Фрилансеры-одиночки без команды (некому пересылать конспект).
- Корпорации с жёсткими требованиями к безопасности (не пустят сторонних ботов).
- Те, кто не пользуется Telegram как рабочим инструментом.

## 4. Пользовательские сценарии

- **US-1.** Как руководитель, я хочу отправить боту ссылку на встречу и получить конспект в Telegram, чтобы не тратить время на ручное конспектирование.
- **US-2.** Как руководитель, я хочу переслать конспект в чат команды одним нажатием, чтобы вся команда видела договорённости и задачи.
- **US-3.** Как руководитель, я хочу получить полную расшифровку в Google Doc, чтобы использовать её для работы с AI (карты развития, вакансии, обратная связь).
- **US-4.** Как предприниматель, я хочу внедрить бота своим менеджерам, чтобы контролировать качество их встреч.
- **US-5.** Как пользователь, я хочу настроить бота за 2 минуты через Telegram без регистрации на сайте.

### 4.1. Онбординг

1. `/start` → бот создаёт юзера по `telegram_id`, кратко объясняет, что умеет.
2. **Согласие на обработку ПД (152-ФЗ)** — бот показывает текст согласия с двумя кнопками «Согласен» / «Не согласен». Без согласия любая другая команда отвечает «нужно согласие, нажми /start». При согласии — фиксируется `consent_at = now()`.
3. В release 0.1 бот ведёт пользователя через согласие и оплату после исчерпания триала. Привязка Google включается только в будущем Google-режиме; до этого приём ссылок Google не блокирует.

### 4.2. Привязка Google (post-0.1)

1. Бот выдаёт ссылку на OAuth-авторизацию (scope `drive.file`).
2. Юзер соглашается → бот получает токены → создаёт в Drive юзера папку «Транскрибации созвонов» → сохраняет `folder_id` юзера.
3. Бот подтверждает успех.

### 4.3. Триал и оплата (F6, F7)

1. Первые 3 часа — бесплатно. Внутри системы учет ведется в минутах.
2. После исчерпания триала или досрочно по запросу — бот предлагает оплату по прямой ссылке ЮKassa (см. `docs/payments.md`).
3. После успешной оплаты — активна подписка с лимитом 15 часов/мес; публично говорим «месяц», внутри период считается как 30 дней.
4. Длительность результата приходит от поставщика в секундах; при списании секунды отбрасываются, но ненулевая встреча короче 60 секунд списывает 1 минуту.

### 4.4. Основной сценарий — happy path

1. Юзер присылает ссылку на встречу в чат бота.
2. Бот проверяет права (триал или активная подписка с остатком минут), резервирует до 60 минут из одного источника.
3. Через API поставщика транскрибации (текущий prod — s2t под наблюдением; mymeet — рабочий fallback) подключается бот-участник к звонку.
4. По завершении звонка бот получает транскрипт по спикерам; саммари F3 — отдельным шагом через OpenRouter, если provider не отдал готовый конспект.
5. Собирает два markdown-артефакта: полную расшифровку и конспект.
6. Шлёт юзеру финальное сообщение и файлы в Telegram. Google Doc остаётся post-0.1 режимом.

### 4.5. Проверка остатка

`/balance` → бот показывает оставшиеся часы/минуты и дату следующего сброса.

## 5. Функционал MVP — что ДЕЛАЕМ

| # | Функция | Описание |
|---|---|---|
| F0 | Согласие на обработку ПД | При первом `/start` — обязательный шаг: текст согласия (152-ФЗ) и две кнопки. Без согласия — приём ссылок заблокирован. `consent_at` фиксируется в БД. |
| F1 | Подключение к встрече | Пользователь отправляет ссылку на встречу в чат бота. Бот подключается как участник через API поставщика транскрибации. |
| F2 | Запись и транскрибация | Бот записывает аудио, преобразует в текст с разделением по спикерам; отображаемые имена участников могут прийти от платформы встречи или поставщика транскрибации. |
| F3 | Конспект с задачами | AI генерирует структурированный конспект: ключевые темы, решения, задачи с ответственными. На пути Speech2Text конспект делает наш `Summarizer` через OpenRouter; mymeet может вернуть provider-summary из шаблона. |
| F4 | Отправка в Telegram | Конспект + полная расшифровка приходят сообщением в Telegram. |
| F5 | Google Doc | Автоматически создаются два Google Doc (транскрипт + конспект), ссылки в Telegram. *Post-0.1; release 0.1 доставляет результат `.md`-файлами в Telegram.* |
| F6 | Бесплатный триал | Первые 3 часа бесплатно, затем предложение оплатить подписку. |
| F7 | Оплата через Telegram | Оплата подписки из бота по прямой ссылке ЮKassa: бот присылает кнопку оплаты, ЮKassa принимает карту и возвращает статус через API. При `RECURRING_PAYMENTS_ENABLED=true` автопродление включается по умолчанию после оплаты; при `false` оплата разовая. Способ оплаты сохраняется только если ЮKassa вернула `payment_method.saved=true`. См. `docs/payments.md`. |
| F8 | Настройка через Telegram | Вся настройка подписки через чат с ботом. OAuth Google добавляется в post-0.1 Google-режиме. |
| F8.5 | Переподключение Google | Команда `/reconnect` — повторный OAuth. Post-0.1: используется при отзыве доступа, протухании refresh-токена в Testing mode (раз в 7 дней), 401 на refresh во время Job. После reauth «будятся» все Job юзера в статусе `awaiting_reauth`. |
| F9 | Пуши о подписке | Транзакционные дожимы в Telegram: триал заканчивается, пользователь смотрел оплату и не оплатил, платных часов осталось меньше часа, платные часы закончились до календарного expiry, подписка истекает через 3 дня, подписка истекла. После billable terminal path при нулевом остатке бот отправляет отдельное сообщение `Баланс закончился`. Для подписок с включённым recurring worker автопродлевает период; `/balance` показывает статус автопродления, даёт отключить его и запустить оплату нового периода. |

## 6. Антискоуп — что НЕ ДЕЛАЕМ в MVP

Защита от расползания скоупа. Любое добавление требует осознанного решения и обоснования.

- Гарантированное обезличивание спикеров до «Спикер N».
- Автоподключение из календаря (v1.1).
- Подтягивание названия встречи из календаря.
- Мобильное приложение — всё через Telegram.
- Веб-интерфейс / личный кабинет.
- Редактирование транскрипта внутри сервиса.
- Интеграции с CRM, Notion, Trello, Asana и прочими (v2.0).
- Запись видео (только аудио-транскрибация).
- Встроенный AI-чат для вопросов по встрече.
- Мультиязычность / автоопределение языка.
- Командные аккаунты и роли.
- Аналитика встреч / дашборды.
- Реферальные ссылки (v2.0).
- Несколько тарифов (v2.0).
- Частичные refund'ы и self-service refund. Для MVP возвраты выполняются оператором вручную через ЛК ЮKassa/поддержку; REST refund остаётся техническим smoke/fallback без пользовательского admin-flow.
- Anti-fraud защита от триал-эксплоита через многократные Telegram-аккаунты (на закрытой бете риск низкий).
- Отдельная команда `/account` — `/balance` покрывает базовую нужду.

## 8. Монетизация

Месячная подписка с лимитом часов. Один тариф на старте.

| Параметр | Значение |
|---|---|
| Бесплатный триал | 3 часа без оплаты |
| Цена подписки | 1 990 ₽/мес за 15 часов |
| Лимит | 15 часов/мес (cap для защиты маржи) |
| Оплата | Из Telegram по прямой ссылке ЮKassa |

**Цена запуска — 1 990 ₽/мес** (решение заказчика 2026-06-19). Маржа зависит от тарифа поставщика транскрибации (см. ниже).

### 8.1. Контракт почасового учета

- Пользователь видит часы: 3 часа trial и 15 часов в месячной подписке.
- Runtime и БД считают только минуты.
- На старте Job резервируется до 60 минут из одного источника: ближайшая активная подписка, иначе trial.
- До точки оказания услуги cancel/provider/start error возвращает весь резерв.
- На `done` или `failed_summary` billing финализируется по фактической длительности результата.
- Если duration меньше резерва, unused reserve возвращается в исходный источник.
- Если duration больше резерва, extra добирается только из исходного источника и только при достаточном активном остатке.
- Следующая подписка не списывается для перерасхода текущей встречи; долг и negative balance не создаются.
- До созвона не предупреждаем о возможном перерасходе. Если после billable terminal path остаток стал 0, отправляем отдельное сообщение `Баланс закончился`.

**Дополнительный риск:** финмодель построена на предположении usage-тарифа у поставщика транскрибации. У mymeet API-тариф за минуты — 1,5-2 ₽/мин = 90-120 ₽/ч (линейно), на масштабе даёт **отрицательную маржу**; s2t — рублёвый флэт «24 Часа» (17 600 ₽/мес: 24 ч/сут, 3 потока, сверх лимита 0,40 ₽/мин ≈ 24 ₽/ч), эффективно ~24-35 ₽/ч на масштабе, маржа положительна. Именно экономика определила выбор s2t экономически целевым (финал 2026-06-19), но s2t остаётся live-риск-треком из-за зомби/пустых результатов. Расчёты — `docs/api/mymeet/README.md` §2.1, тарифы S2T — `docs/api/speech2text/README.md` (раздел «Тарифы»). Цена запуска зафиксирована (1 990 ₽), устойчивость маржи зависит от:
1. Загрузки флэт-тарифа s2t «24 Часа» (экономически целевой, на масштабе держит маржу — стоит мониторить фактическую утилизацию). Mymeet fallback (per-minute) на масштабе убыточен, но нужен как функциональная страховка.
2. Учёта НДС +22% на комиссию эквайринга (действует с 01.01.2026, см. `docs/payments.md` §3).

Ранний план «закрытая бета бесплатно / ≤500 ₽» заменён решением о запуске по 1 990 ₽ (2026-06-19); ранние когорты можно поощрять скидкой по усмотрению заказчика.

## 10. Дорожная карта

**Стратегия после встречи 5 июня:** идём слайсами от минимального рабочего продукта к полному F0–F9. Каждый этап добавляет одну подсистему. Это позволяет получить рабочий бот к 30 июня без зависимости от долгоиграющих внешних процессов (ЮKassa, Google verification, B2B-договоры с поставщиками).

### Release 0.1 / MVP candidate (2026-06-25)

Рабочий prod/test контур для проверки гипотезы и обратной связи от 5-10 близких пользователей. Оплата втянута в MVP (решение 2026-06-14) и проверена на test-боте до успешного платежа.

- **В скоупе release 0.1:** F0 (consent), F1 (приём ссылки), F2 (транскрипция через работающий API), F3 (AI-конспект через `Summarizer`), F4 (отправка в Telegram файлом + сообщением), F6 (триал), F7 (оплата ЮKassa), F8min (`/start`, `/balance`, `/help`), F9 (пуши).
- **Post-0.1:** F5 (Google Doc) и F8.5 (`/reconnect`/`awaiting_reauth`) остаются отдельным Google-слайсом через Testing mode. Release 0.1 доставляет результат `.md`-файлами в Telegram.
- **Оплата (решение 2026-06-14, обновлено #26/#27/#9):** F6 триал + F7 ЮKassa direct payment links (`docs/payments.md`) работают по контракту 3 часа trial и 15 часов/мес с минутным учетом. Ветка `feature/yookassa-payment-links` добавила email для чека, `POST /v3/payments`, кнопку `confirmation_url`, polling `GET /v3/payments/{id}`, full refund по `payment.id`. Старый Telegram Payments E2E до `successful_payment` остаётся baseline-историей, но не целевым go-live потоком. Test payment-link smoke, технический refund smoke и prod live payment-link + recurring smoke пройдены; успешные prod-платежи пока были owner smoke, первая внешняя оплата остаётся мониторинговым событием.
- **F3 конспект:** s2t отдаёт только транскрипт, саммари формируем сами через OpenRouter; mymeet fallback может вернуть готовое саммари из шаблона. Качество промпта проверяем живыми прогонами.
- **Telemost** — поддержан обоими поставщиками. Отдельного этапа не требует.
- **Вне скоупа release 0.1:** Google-доставка, Google Production (brand verification), v1.1-фичи.

### Google Drive — post-0.1

F5 + F8.5 реализуются после release 0.1 (issue #13, P2): Google Doc в Drive юзера, `/reconnect`, `awaiting_reauth`, Testing mode. Затем переход в Production: brand verification для non-sensitive `drive.file` — **~2-3 рабочих дня ревью Google**, не 4-6 недель (та оценка относилась к sensitive/restricted-скоупам, которых у нас нет). Реальный prerequisite — наша инфра (homepage + privacy на домене + Search Console); канон — `docs/google.md` §7. После Production снимается 7-дневное протухание refresh-токенов Testing mode.

### v1.1 (после 50 пользователей) — гипотеза

- Автоматическое подключение ко встречам из Google Calendar.
- Кастомизация формата конспекта (шаблоны).
- Поддержка Microsoft Teams.

### v2.0 (далёкий горизонт) — гипотеза

- База знаний по встречам с AI-поиском.
- Интеграция с таск-трекерами (Notion, Trello).
- Командные аккаунты с ролями и дашбордом.
- Мультиязычность.

*v1.1 и v2.0 — только гипотезы, не обязательства. Решение о развитии — на основе метрик MVP и обратной связи.*

## 11. Риски и допущения

### Допущения, на которых строится план

- ЦА готова платить ~2 000 ₽/мес за инструмент для встреч.
- Руководители проводят достаточно онлайн-встреч для регулярного использования.
- Люди готовы пустить стороннего бота на свои встречи (privacy-барьер преодолим).

### Риски

| Риск | Вероятность | Последствия | Митигация |
|---|---|---|---|
| Privacy-барьер: люди не хотят пускать бота | Средняя | Низкая конверсия | Триал + кейсы пользователей |
| Качество транскрибации/диаризации недостаточно | **Средняя** (см. ниже) | Отток после триала, NPS<40 | Тест диаризации на текущем prod-провайдере и fallback; при <85% — LLM-постпроцессинг по транскрипту для переразметки спикеров |
| Конкуренты снизят цены до нуля | Средняя | Давление на маржу | Дифференциация через Telegram UX |
| Разработчик срывает сроки | Средняя | Затягивание запуска | Недельные спринты, демо каждые 2 недели |
| Надёжность s2t (экономически целевой, выбран по экономике 2026-06-19) | **Подтверждённый live-риск** (зомби/пустые результаты в ручных тестах) | Ошибки встреч, возврат квоты, плохой UX | Mymeet fallback через `TranscriptionProvider`; live-серия s2t/OpenRouter перед публичным запуском; план В — Recall.ai (без Telemost) или собственный Whisper-pipeline |
| Recall.ai изменит цены/условия | Низкая | Рост себестоимости | Мониторинг альтернатив |
| Мало встреч у ЦА | Средняя | Низкий usage, отток | Триал покажет реальную частоту |

**Обоснование среднего риска по диаризации:** у s2t независимых WER/диаризация-метрик нет вообще (только заявленные ~97%); у mymeet независимый тест VC.ru показал ~70% реальной точности на однопотоковом аудио Zoom/Meet/Telemost (заявлено 96-98%). Это бьёт прямо по ключевому ценностному предложению «транскрипт по спикерам». Обязательный шаг — собственный тест текущего prod-провайдера и fallback с 3-спикерной встречей. При <85% — подключение LLM-постпроцессинга для переразметки спикеров по контексту.
